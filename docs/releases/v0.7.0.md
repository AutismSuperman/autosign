# AutoSign v0.7.0

发布日期：2026-10-22

## 本次变更

### 签到奖励不再显示成「余额差」

之前重登类站点（AgentRouter 等）的「签到 +$xx」显示的其实是**重登前后余额差**。
这个差值包含同时段的正常消耗与其它入账，所以同一批账号会出现
+$20.90、+$21.71、+$21.37 这种互不相同、每天都变的数字，
而站点实际的每日奖励是固定的。

现在奖励金额只认站点自己的今日发放记录：

- 签到接口返回的奖励，或站点日志里的今日签到 / 今日到账记录；
- 读不到金额时只显示「已签」，不再拿余额差凑一个数字；
- 超过 $1000 的金额视为换算错误，不显示。

你之前那些显示错误的账号，升级后不需要重新签到 —— 历史回执会自动标注为
「余额差」并停止展示金额，下次签到后换成站点记录里的真实金额。

### 金额换算按站点自己的单位

有的站点不用默认的 500000 quota = $1，而是自定义配额单位。
之前所有金额一律按默认值换算，遇到这类站点，可用 / 累计金额会整体差若干倍。

现在启动时会读取站点的 `quota_per_unit` 并记住，之后所有金额都按它换算。
已经存在的站点会在启动后自动补查一次，无需手动重新添加。
余额换算也不再套用「小值当美元」的规则 —— 那条规则只适用于奖励字段，
用在余额上会把 $0.001 显示成 $500。

### GitHub 账号不再每次都要手动点「重新授权」

之前必须手动授权有两个原因，都已修掉：

- GitHub 现在下发的是 `__Host-user_session_same_site`（带 `__Host-` 前缀），
  而旧代码只认 `user_session`。于是分区里明明保留着登录态，也被判成「没有」，
  自动重登直接放弃。现在两种名字都认。
- 分区是浏览器内核的磁盘状态，换电脑、重装、清缓存后就没了。现在授权成功后
  会把 GitHub / Linux DO 的登录态另存一份加密备份（与站点会话同一套系统加密），
  分区为空时先写回去再走授权，多数情况不用你输密码。备份在重新授权后自动更新。

另外新增后台自动重试：某个账号上次恢复失败（比如正好撞上网络抖动或限流），
每 30 分钟会自动再试一次，通了就自己清掉「需要重新授权」标记。

### 批量刷新 / 签到可以中途停止

批量任务进行中，进度条右侧有「停止」按钮。点了之后当前账号处理完就收工，
已经完成的结果会保留，收尾提示写明实际处理了几个。

之所以不在点击瞬间硬中断：签到请求可能已经发到站点，强行掐断会让本地
不知道到底签没签。等当前这一项跑完再停，状态才是一致的。

### 签到会跳过今天已经签过的账号

批量签到与定时任务遇到当前奖励周期内已有成功回执的账号，直接跳过、不发请求：

- 不会重复撞人机验证；
- 不会对重登类站点做无意义的登出重登；
- 收尾提示会写明「其中 N 个今日已签，自动跳过」，这些计入成功。

「登录即得」类站点（GoRouter 等）现在也会先核对站点记录：今日已发放就报「今日已签」，
不再一律提示「请刷新额度确认到账」。

### 界面下发的数据不再包含会话凭据

会话 Cookie、访问令牌、第三方登录态备份只在主进程内存与加密文件之间流动。
之前它们会随配置一起下发到界面进程，本次收紧了这个边界（界面并不需要这些字段）。
同时加了测试逐字段钉住，避免以后新增字段时漏掉。

## 需要你手动做的

- 覆盖安装即可，站点、账号与凭据都会保留，不需要重新授权。
- 如果升级后仍有账号显示「需要重新授权」，点一次即可 —— 那次授权成功后备份就建好了，
  之后正常情况下不会再要求你操作。
- 首次启动会为已存在的站点补查配额单位、为已存在的账号补存登录态备份，
  这一步需要联网，失败会在运行日志里记录（不影响使用，下次启动会重试）。

## 已知问题

- 分区登录态备份依赖系统加密（Windows DPAPI / macOS 钥匙串 / Linux libsecret）。
  系统加密不可用时会拒绝写入备份，此时静默重授权仍可工作，但换电脑后需要授权一次。
- 若站点自身把每日奖励改成动态金额，界面显示的就是站点记录里的那个值，不会再与「$25」比对。
- macOS 的应用内「一键重启安装」仍不可用，需要 Apple 开发者证书签名才能启用；
  更新方式是「收到通知 → 下载安装包 → 覆盖安装」。
