# AutoSign v0.4.0

发布日期：2026-10-20

## 本次变更

### 重登领取不再把账号弄掉线

AgentRouter、AnyRouter 这类站点没有签到接口，当日额度是在登录动作里发放的，
所以「签到」实际上要经历一次登出再重登。旧版本会先把账号真的登出，
再指望隐藏窗口靠残留的登录状态自己登回来 —— 但登出恰好清掉了它要依赖的
那份状态，结果账号掉线、当天额度没领到，还要求你手动重新授权。

现在流程反过来了：**先确认能不能登回来，再决定要不要登出**。
只要保存的凭据或第三方登录状态不足以自动登回，就不登出，账号保持原样，
只如实告诉你需要重新授权。宁可当天不领，也不会让你第二天要重新登录。

### GitHub 账号可以完全自动重登

在「账号」页给 GitHub 凭据补上密码后，即使分区里的 GitHub 登录状态过期，
程序也会用这个密码在后台重新登录一次并完成授权，全程不弹窗。
之前这条路径的填表参数是空的，从未真正生效过。

### 每个账号都有「重新授权」入口

以前这个按钮只在账号被判定为会话失效时才出现，而签到失败并不会留下
这个判定，于是会出现「报了错但界面上找不到地方重新登录」。
现在每个账号行都常驻「重新授权」，会话失效时它会变成主按钮，
排在「刷新额度」前面。

重新授权对话框还会自动选中该账号原来用的那份凭据，不用再自己找。

### 修正重新授权后登录状态存错位置

旧版本在做「重新授权」时，把 GitHub 的登录状态写进了一个临时位置，
而账号之后读取的是它自己的位置。两者对不上，所以每次静默重登都会
报「找不到登录状态」，只能一次次手动授权。这是「每天都要重新登录」
的直接原因，现已修正。

### 后台保活不再做无用请求

没有访问令牌、只靠会话 Cookie 的账号（AgentRouter 就是这种），
以前每 5 分钟会发起一次注定失败（404）的令牌续期请求。
现在直接跳过，不再白白消耗流量。

## 需要你手动做的

- 已安装的用户不需要重新配置，覆盖安装即可。
- **之前签到失败过、账号显示「会话失效」的，请点一次「重新授权」**。
  旧版本写入的登录状态位置是错的，修复后需要正常授权一次作为起点。
- 希望 GitHub 账号长期免手动，建议到「账号」页给对应的 GitHub 凭据补上密码。
  只靠登录状态也能自动重登，但 GitHub 侧的状态本身有期限，到期后仍需手动授权一次。

## 已知问题

- 没有保存密码、且分区里的 GitHub 登录状态确实已过期时，静默重授权无法完成，
  仍需要手动授权一次。这是第三方授权本身的限制。
- GitHub 要求设备验证或人机验证时，程序会停下来交还给你，不会尝试绕过。
- AnyRouter 的额度发放窗口仍从北京时间 08:00 开始，在此之前重登不会到账。
