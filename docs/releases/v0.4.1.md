# AutoSign v0.4.1

发布日期：2026-10-20

## 本次变更

### 修复 GitHub 账号仍可能掉线的问题

上一版把「先登出再重登」改成了「先确认能登回才登出」，但确认逻辑和实际恢复
逻辑有一处不一致：**没有绑定凭据、分区里却还留着 GitHub 登录态的账号**，
确认环节判定「可以登回」，真正恢复时却因为「没有凭据」直接失败。
结果是账号被登出后再也登不回来。

现在这种情况会直接走静默授权：GitHub 的登录状态就存在账号自己的分区里，
只要那份状态还在，重新走一遍授权不需要任何操作，也不要求绑定凭据。

### 「重新登录」与「重新授权」分开

密码登录的账号没有「授权」这一步，之前统一显示「重新授权」会让人以为
要跳转到第三方网站。现在按登录方式区分：密码登录显示「重新登录」，
GitHub / Linux DO 显示「重新授权」，对话框标题与提示也一并跟随。

### 恢复入口只在真正需要时出现

上一版把入口挂在了每个账号上，属于过度补偿。现在改由主进程在确认
「自动恢复也失败」时标记该账号，界面才显示入口；额度刷新成功、
重新登录成功、签到成功后都会自动清除这个标记。

不会误报的情形：风控拦截、限流、网络错误这类失败与会话是否有效无关，
不会触发入口。

### 签到继续走静默重授权

GitHub / Linux DO 账号在会话失效时，默认路径就是静默重新授权，
不弹窗、不需要输入密码。只有分区登录态确实过期、且凭据里没有保存密码时，
才会提示你手动完成一次。

## 需要你手动做的

- 已安装的用户覆盖安装即可，不需要重新配置。
- 上一版若把某个账号登出了，请点该账号的「重新授权 / 重新登录」恢复一次。
- 想让 GitHub 账号在登录态过期后也能全自动恢复，可以到「账号」页
  给对应的 GitHub 凭据补上密码。不补也能用，只是 GitHub 登录状态
  到期时需要手动点一次。

## 已知问题

- GitHub 登录状态本身有期限（通常数周），到期且没有保存密码时仍需手动授权一次。
- GitHub 要求设备验证或人机验证时，程序会停下来交还给你，不会尝试绕过。
- AnyRouter 的额度发放窗口仍从北京时间 08:00 开始，在此之前重登不会到账。
